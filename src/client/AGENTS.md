# Client Rules

适用于 `src/client/` 全域。
测试规则见 `tests/AGENTS.md`；跨层依赖与全仓库规范见根 `AGENTS.md`。

## 本层承担什么

Client 负责：**总控台页**和**能力管理页**的交互与可视化

判断标准：一段代码若回答「界面如何呈现、如何交互」，属 Client；若回答「事实是什么、何时成立、如何持久化」，属 Host。

## 层级边界

- **components（组件）**：负责渲染与用户交互，只消费 props、选择器结果与注入的动作面；不感知网络、持久化与宿主服务细节。
- **hooks（状态组合、生命周期）**：负责把状态、派生数据与动作组合成界面可用的输入；一个 hook 只承担一个职责。
- **lib（纯逻辑）**：纯计算与转换、网络访问、持久化；不得依赖任何 UI 模块。
- **views（页面）**：包含总控台页（概览、审批、工单、事件、来源、设置）和能力管理页（工具、skill、MCP）

## 依赖与纯函数

- **依赖方向单向**：components / hooks 可依赖 lib；lib 不得反向依赖，也不得出现循环依赖。
- 被 lib 与组件共用的纯常量应下沉到 lib 或共享契约，而不是让 lib 反向引用组件。
- 纯计算与状态无关的转换优先实现为纯函数：输入即全部事实，不得隐式读取全局或环境。

## 数据流与数据访问边界

- **单向数据流**：事实流向固定为单向，不得出现反向捷径或旁路
- **网络访问只经统一网络边界与注入面**：组件与 hook 不得自建第二条数据访问路径（不得直接发起请求、不得绕过注入面自取宿主服务）；
- 端点名、协议常量等一律引用共享契约，不得在调用点硬编码字面量；
- **稳定错误码由调用方按语义处理**，不得只显示通用文案后静默继续；

## 文案与组件样式

- 面向用户的文案**必须走词典**，`zh` / `en` 同步新增，禁止在组件内硬编码用户可见字符串；
- 界面通用设计 token 从宿主侧读取，不得自建通用设计变量，宿主侧没有才自建。
- 样式按页面/领域拆分在 `styles/`，组件只从 `styles/index.ts` 导入 `CONSOLE_CSS`；
- 设计变量只在 `styles/tokens.ts` 定义（分平台引用、插件刻度、官方对齐区三段），其他样式文件只允许 `var(--pa-*)` / `var(--dsw-*)`，不得写字面量；
- Tab 条使用独立的 `--pa-tabs-*` Token 锁死与官方的对齐值，禁止随排版刻度调整。
