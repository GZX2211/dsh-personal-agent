## 1. 背景

Personal Agent（下称 PA）当前的运行方式：

- Router 会话接收信号（用户消息、定时事件、感知事件），决定 `dispatch` / `append` / `reply`；
- `dispatch` / `append` 生成工单，工单在独立的 Worker 会话里后台执行；
- Worker 在需要人决定时提交审批，审批在右侧栏总控台处理；
- 账本（L2 events）是唯一事实来源，工单阶段、审批状态、信号结局都由事件序列派生；
- 总控台现有页面：审批、工单、事件、来源、设置；「概览」尚未实现。

概览页的定位：

- 总控台的**默认页**；
- 一眼看到 PA 在实际使用中发生了什么；
- **只读 + 轻交互**（跳转），不写账本、不直接审批；
- 不是详细监控页，不复制审批/工单/事件列表。

## 2. 目标与验收

概览页要回答四个问题：

1. **它活着吗？** —— 状态脉搏；
2. **需要我吗？** —— 注意力条；
3. **它现在在做什么？** —— 进行中的执行会话（含上下文）；
4. **今天做了什么？** —— 今日数字 + 7 天活动。

「一眼」验收：

> 打开概览，3 秒内能回答：有没有待审批或异常、几个工单在跑、它们卡在哪/上下文如何、今天完成/失败/事件多少。

非目标：

- 完整审批 / 工单 / 事件列表；
- 每个 Worker 的工具调用流、日志尾部、token 成本；
- 任务进度条、健康分；
- 在概览里直接审批、停止、重试；
- 搜索、筛选、时间范围选择器。

## 3. 已定决策（实施时不再改）

| 决策 | 取值 |
|---|---|
| 页面方向 | B：按「现在 / 今天」组织，执行会话是主角 |
| 默认页 | 概览；审批仍保留标签徽标 |
| 上下文阈值 | 有效窗口 = 标称窗口 × 0.8；有效占用 ≥60% 标黄，≥80% 标红 |
| 上下文进注意力条 | 有效占用 ≥80% 才进（含 80% 边界，与标红一致） |
| 累计值 | 工单 / 审批 / 事件总数降到底栏 10px，不做主视觉 |
| 注意力条 | 最多 2 条，其余折叠成「另有 N 项」 |
| Worker 行 | 最多 5 行，其余折叠成「还有 N 个执行会话」 |
| 滚动 | 整页滚动，不嵌套滚动 |
| 交互 | Worker 行 → 执行会话；注意力条 → 对应页；脉搏 → Router 会话 |
| 数据面 | 扩展现有 `/snapshot`，不新增 HTTP 端点 |
| 契约兼容 | 新字段可选，客户端对缺失值降级 |
| 依赖 | 不新增第三方依赖 |

## 4. 页面结构

### 4.1 区块顺序

固定为：

```
状态脉搏  →  注意力条（有才显示）  →  进行中（Worker 舰队）  →  今天  →  底栏
```

三个域（审批 / 工单 / 事件）的数据分布在各自最该出现的位置，不按域分三块报表。

### 4.3 尺寸与滚动

- 容器：`.pa-overview`，`display:flex; flex-direction:column; flex:1 1 auto; min-height:0;`，`overflow-y:auto`，`padding:12px 16px 16px`，`box-sizing:border-box`。父级 `.pa-console__body` 是 flex 列，概览必须能长高。
- 区块间距：14–16px；同级卡片内边距 8–12px。
- 页面宽度按右侧栏自适应，目标 320–480px；320px 下不横向滚动。
- 底栏用 `margin-top:auto` 在内容较短时贴底；内容变长时自然下移。

- 内容高度参考：0 Worker ≈ 360px；2 Worker ≈ 600px；5 Worker ≈ 760px。5 个 Worker + 图表时允许整页滚动。

### 4.4 视觉语言

- 颜色、圆角、字号、阴影全部取宿主 design token，不新增硬编码色值。
- 字号沿用现有刻度：14 正文 / 13 次要 / 12 小字 / 11 徽标；数字 `font-variant-numeric: tabular-nums`。
- 语义色：
  - 蓝（`--dsw-alias-state-business-primary`）：执行中 / 投递；
  - 琥珀（`--dsw-alias-state-warn-primary` / `--dsw-alias-state-warn-label`）：等待审批 / 上下文偏高 / 注意力；
  - 红（`--dsw-alias-state-error-primary`）：失败 / 离线 / 上下文临界；
  - 灰（`--dsw-alias-label-tertiary` / `--dsw-alias-state-idle-primary`）：空闲 / 未知；
  - 绿（`--dsw-alias-state-success-primary`）：健康脉搏 / 完成。
- 图形只表达关系，不做装饰：
  - 槽位段：容量；
  - 上下文小环：占用；
  - 7 天柱：活动趋势。
- 动效只来自官方 `StateDot` 的 ongoing 状态；不额外写动画，`prefers-reduced-motion` 下自然静止。
- 状态不能只靠颜色：每个状态都有文字（「等待审批」「会话不在线」「上下文 84%」）。

## 5. 指标与计算口径

### 5.1 上下文（最重要，先定死）

#### 公式

```text
advertised = session.requestContext()?.contextWindow     // 模型标称窗口
effective  = floor(advertised × 0.8)                     // 有效窗口：标称打八折
used       = usage.inputTokens
           + (usage.cacheReadTokens ?? 0)
           + (usage.cacheWriteTokens ?? 0)               // 只算提示词侧
ratio      = used / effective

level = ratio >= 0.80 ? 'critical'
      : ratio >= 0.60 ? 'warn'
      :                  'normal'
```

为什么是 0.8：官方标称的 1M 上下文经常达不到，按 80% 折算作为有效容量，给长回合留安全边界。这是产品策略，不是模型事实，代码里必须写注释说明。

为什么只用提示词 token：`TokenUsage` 的计数是互斥的，`inputTokens` 是不含缓存的输入，缓存命中/写入要单独加。不要用 `totalTokens`（含输出），也不要把 `outputTokens` 加进来——输出是否进入下一次上下文由适配器决定，简单相加会误导；下一次请求的 `usage` 会自然覆盖它。0.8 的折算已经留了安全余量。

#### 阈值与示例（以标称 1M 为例）

| used | effective | ratio | 行内显示 | 级别 | 进注意力条 |
|---:|---:|---:|---:|---|---|
| 479k | 800k | 59.9% | 59% | normal | 否 |
| 480k | 800k | 60% | 60% | warn（黄） | 否 |
| 639k | 800k | 79.9% | 79% | warn（黄） | 否 |
| 640k | 800k | 80% | 80% | critical（红） | 是 |
| 800k | 800k | 100% | 100% | critical（红） | 是 |
| 880k | 800k | 110% | 110% | critical（红，环画满） | 是 |

- 显示百分比用 `Math.floor(ratio × 100)`，避免 59.9% 显示成 60% 却不标黄。
- 阈值比较用原始 `ratio`，不用取整后的百分比。
- 80% 边界同时触发标红与注意力条；不要出现「标红了但注意力条不出现」的裂缝。

#### 行内展示

```
上下文 84% ◔
```

- “上下文”是 9.5px 的标签，必须有，不能只放一个环——否则会被读成任务进度。
- 百分比 10.5px，tabular-nums。
- 小环 16px：轨道 `--dsw-alias-border-l2`，填充按 level 取语义色；`ratio` 超过 1 时环画满，数字显示真实百分比。
- 环用 SVG：`r=7.2`，周长 `2πr≈45.24`；`stroke-dasharray="{min(ratio,1)*45.24} 45.24"`，`rotate(-90)`。
- 无窗口：显示 `上下文 168k`（已用 token），环画虚线，tooltip 说明“模型未报告窗口”。
- 无请求：显示 `上下文 —`，tooltip“还没有模型请求”。
- 离线：显示 `上下文 —`，行状态已经写明“会话不在线”。
- tooltip 文案（有窗口）：
  > 上次请求 640k / 有效 800k · 剩余 160k（标称 1M × 80%）

- tooltip 文案（无窗口）：
  > 上次请求 168k · 模型未报告窗口

- “上次请求”四个字要有：最后一条 `assistant/message` 的 usage 是上一次请求的占用，新输入可能还没进上下文；不要声称精确到当前这一秒。
- 2 秒轮询，上下文最多落后 2 秒；这是可接受的。

#### 边界

- `contextWindow` 缺失、为 0、负数、非有限值：按“无窗口”处理，不算比例。
- `usedTokens` 缺失：按“无请求”处理。
- 路由切换导致 `contextWindow` 变化：以最近一条 `request/context` 为准。
- 压缩（compaction）后 usage 会下降：下一次 `assistant/message` 自然修正，不需要额外逻辑。
- 比例 > 100%：环画满、数字红色，不截断真实值。

### 5.2 今天

- 以**本地自然日 00:00** 为起点；Host 计算 `activity.today.start`，客户端用它过滤审批和工单，保证三格口径一致。
- 审批已处理：`approval.decidedAt >= today.start` 的数量。
- 工单完成/失败：`ticket.endedAt >= today.start` 且 `outcome` 对应。
- 工单平均耗时：今天结束的工单 `endedAt - createdAt` 的平均值；只放 tooltip，不占可见行。
- 事件今日：Host 聚合的 `activity.today.delivered + filtered`。
- 当前待审批：全部 pending（不是今天），显示在审批格的副行，提醒“现在还有”。
- 信号的今日数**必须 Host 聚合**：快照里的 `signals` 只有最近 200 条，客户端数今日会漏。

### 5.3 累计值（底栏）

- 累计工单：`stats.tickets.total`；
- 累计审批：`stats.approvals.pending + stats.approvals.decided`；
- 累计事件：`stats.signals.total`；
- 来源运行中：`sources.filter(s => s.status === 'running').length`；
- 定时任务：`timers.filter(t => t.active).length`；
- 来源异常：`sources.filter(s => s.status === 'error').length`，底栏追加红色「N 异常」。

### 5.4 状态脉搏

一行，回答“活着吗”。

状态优先级：

1. 没有 `routerSessionId` → `Router 会话未就绪`（琥珀）；
2. 有进行中的 Worker（`stats.tickets.running + blocked > 0`）→ `运行中`（ongoing）；
3. 有运行中的来源 → `感知中`（done）；
4. 其他 → `空闲`（idle）。

右侧：

- 正常：`最近活动 {相对时间}`；
- 无任何活动：`还没有活动`；
- 有快照但连接失败：`数据可能已过期`（灰色，配合错误横幅）。

“最近活动”取以下最大值，而不是只看信号：

- 最新信号 `receivedAt`；
- 工单 `updatedAt`；
- 审批 `createdAt` / `decidedAt`；
- Worker `lastActivityAt`。

脉搏可点：有 `routerSessionId` 时点击打开 Router 会话；否则不可点。

### 5.5 注意力条

只在有事时出现，最多 2 条，按优先级：

| 优先级 | 条件 | 严重度 | 主文案 | 副文案 | 点击目标 |
|---:|---|---|---|---|---|
| 1 | pending 审批 > 0 | warning | `1 条审批等你处理` / `N 条审批等你处理` | 最久等待 · 最高风险 · 占用槽位 | 审批页 |
| 2 | 有 worker `live === 'offline'` | danger | `1 个执行会话不在线` / `N 个...` | 无 | 工单页 |
| 3 | 有来源 `status === 'error'` | warning | `1 个感知来源异常` / `N 个...` | `可能漏掉变化` | 来源页 |
| 4 | 有 `ticket.interrupted` | warning | `1 张工单已中断` / `N 张...` | 无 | 工单页 |
| 5 | 有 `context.level === 'critical'` | danger | `1 个执行会话上下文 ≥80%` / `N 个...` | 无 | 单个→会话；多个→工单页 |

规则：

- 同一类只出一条，用 `count` 表达数量。
- 同一张工单同时 offline + interrupted：只按 offline 计（更严重）。
- 同一张工单同时 blocked + offline：审批条和 offline 条都可能出现（审批仍需要人知道）；按上表顺序。
- 审批的「占用槽位」只算 `stats.tickets.blocked`（被审批卡住的工单），独立审批不占槽位；`blocked > 0` 时才追加。
- 审批的「最高风险」取 pending 中最高：high > medium > low > 未标注；没有 risk 时不显示。
- 审批的「最久等待」取 pending 中最早的 `createdAt`。
- 超过 2 条：显示前 2 条 + `另有 N 项`（不可点，提示用户去对应页）。
- 没有条目：整块不渲染，不要占位。

行结构：

```
[Tag: 审批]  1 条审批等你处理                      →
             已等待 6 分钟 · 最高风险 高 · 占用 1 个槽位
```

- Tag 用官方 `Tag`，tone 按严重度：warning / danger。
- 主文案 12px；副文案 10.5px tertiary；箭头右侧。
- 整行是按钮，`aria-label` 包含主文案与副文案。

### 5.6 Worker 展示状态

判定顺序（先命中先算）：

| 顺序 | 状态 | 条件 | 圆点 | 副文案 | 右侧 |
|---:|---|---|---|---|---|
| 1 | `waiting` | `ticket.stage === 'blocked'` | warning | `等待审批` | `已等 4 分钟` |
| 2 | `interrupted` | `ticket.stage === 'running' && ticket.interrupted` | warning | `已中断` | 相对最后活动 |
| 3 | `offline` | `runtime.live === 'offline'` | error | `会话不在线` | 相对最后活动 |
| 4 | `unknown` | `snapshot.workers` 缺失（旧快照） | idle | `状态未知` | 相对最后活动 |
| 5 | `starting` | `runtime.live === 'running' && runtime.turn === 0`，或 `idle && turn === 0` | ongoing | `启动中` | `刚刚` |
| 6 | `running` | `runtime.live === 'running'` | ongoing | `第 N 轮 · 12 分钟` | 相对最后活动 |
| 7 | `idle` | `runtime.live === 'idle'` | idle | `空闲` | 相对最后活动 |

- 排序：`waiting` → `running` → `starting` → `interrupted` → `offline` → `idle` → `unknown`；同类按 `lastActivityAt` 倒序，再按 `dispatchedAt` 倒序。
- 最多显示 5 行；超出显示 `还有 N 个执行会话`，点击去工单页。
- 整行是按钮，点击打开对应执行会话（`workerSessionId`）。
- 行内不再放审批/停止/重试按钮。

行结构：

```
● 修复登录超时                    上下文 84% ◔
  工单 #a1b2c3 · 第 3 轮 · 12 分钟            刚刚
```

- 标题 12.5px，单行省略；`title` 属性给完整标题。
- 右侧上下文 chip 固定，不参与省略。
- 副行 10.5px tertiary：工单短码、轮次、已运行；右侧最后活动。
- 等待审批时副行只到「等待审批」，右侧显示等待时长，不再重复最后活动。

### 5.7 槽位

- `occupied = stats.tickets.running + stats.tickets.blocked`；
- `maxWorkers = snapshot.capacity?.maxWorkers ?? MAX_WORKERS.defaultValue`；
- 头部：`进行中 {occupied} / {maxWorkers}` + 槽位段 + `排队 {stats.tickets.queued}`（排队为 0 时隐藏）。
- `maxWorkers <= 8`：渲染 `maxWorkers` 个小段，前 `running` 段蓝、接着 `blocked` 段琥珀、其余空。
- `maxWorkers > 8`：渲染一条比例条，填充 `occupied / maxWorkers`，tooltip 给「occupied / max」。
- `occupied > maxWorkers`（异常）：段/条画满，数字显示真实值。

### 5.8 今天三格

| 格 | 大数字 | 副行 |
|---|---|---|
| 审批 | 今日已处理 | `已处理 {decided} · 待 {pending}`；pending 为当前值 |
| 工单 | 今日完成 | `完成 {completed} · 失败 {failed}`；失败 >0 时红色；tooltip 可给平均耗时 |
| 事件 | 今日总数 | `投递 {delivered} · 过滤 {filtered}`；activity 缺失时显示 `—` |

- 三格等宽，9.5px 标签、18px 数字、9.5px 副行。

### 7.2 `runtime/index.ts`

```ts
import type { Projection } from '../projector/project.ts'
import type { HostContext } from '../context.ts'
import type { EventStore } from '../store/event-store.ts'
import type { ActivityStats, WorkerRuntimeView } from '../../shared/runtime.ts'
import { ActivityIndex, emptyActivity } from './activity.ts'
import { WorkerRuntimeRegistry } from './workers.ts'

export interface OverviewRuntime {
  activity(now: number): ActivityStats
  workers(projection: Projection): WorkerRuntimeView[]
  close(): void
}

export function createRuntime(options: {
  ctx: HostContext
  store: EventStore
  log?: (message: string) => void
}): OverviewRuntime {
  let activity: ActivityIndex | undefined
  let workers: WorkerRuntimeRegistry | undefined
  try {
    activity = ActivityIndex.open(options.store)
  } catch (error) {
    options.log?.(`overview activity index unavailable: ${describe(error)}`)
  }
  try {
    workers = WorkerRuntimeRegistry.open({ ...options, log: options.log })
  } catch (error) {
    options.log?.(`overview worker runtime unavailable: ${describe(error)}`)
  }
  return {
    activity: now => {
      try {
        return activity?.view(now) ?? emptyActivity(now)
      } catch (error) {
        options.log?.(`overview activity view failed: ${describe(error)}`)
        return emptyActivity(now)
      }
    },
    workers: projection => {
      try {
        return workers?.viewWorkers(projection) ?? []
      } catch (error) {
        options.log?.(`overview worker view failed: ${describe(error)}`)
        return []
      }
    },
    close: () => {
      activity?.close()
      workers?.close()
    },
  }
}

function describe(error: unknown): string {
  return error instanceof Error ? error.message : String(error)
}
```

- `emptyActivity(now)` 返回 7 天全 0（today = 今天 00:00），避免快照端点 500。
- 两个索引分别 try/catch：一个失败不影响另一个，也不影响 tickets/approvals/signals 的返回。

### 7.3 `runtime/activity.ts`

```ts
import type { L2Event } from '../../shared/events.ts'
import type { ActivityStats, DayActivity } from '../../shared/runtime.ts'
import type { EventStore } from '../store/event-store.ts'

interface Bucket {
  delivered: number
  filtered: number
}

export class ActivityIndex {
  readonly #store: EventStore
  readonly #unsubscribe: () => void
  readonly #days = new Map<number, Bucket>()

  private constructor(store: EventStore) {
    this.#store = store
    for (const event of store.events()) this.record(event)
    this.#unsubscribe = store.subscribe(event => this.record(event))
  }

  static open(store: EventStore): ActivityIndex {
    return new ActivityIndex(store)
  }

  record(event: L2Event): void {
    if (event.type !== 'signal/received') return
    // 用 receivedAt 而不是账本 time：前者是信号真正到达的时刻。
    const day = localDayStart(event.payload.receivedAt)
    const bucket = this.#days.get(day) ?? { delivered: 0, filtered: 0 }
    if (event.payload.delivered) bucket.delivered += 1
    else bucket.filtered += 1
    this.#days.set(day, bucket)
  }

  view(now: number): ActivityStats {
    const todayStart = localDayStart(now)
    const days: DayActivity[] = []
    for (let offset = -6; offset <= 0; offset += 1) {
      const start = localDayStartWithOffset(todayStart, offset)
      const bucket = this.#days.get(start) ?? { delivered: 0, filtered: 0 }
      days.push({ start, ...bucket })
    }
    // 只保留窗口内的桶，避免进程长跑后 Map 无限增长。
    const oldest = days[0]?.start ?? todayStart
    for (const key of this.#days.keys()) {
      if (key < oldest) this.#days.delete(key)
    }
    const today = days[days.length - 1] ?? { start: todayStart, delivered: 0, filtered: 0 }
    return { today, days }
  }

  close(): void {
    this.#unsubscribe()
  }
}

/** 本地自然日 00:00。 */
export function localDayStart(time: number): number {
  const date = new Date(time)
  date.setHours(0, 0, 0, 0)
  return date.getTime()
}

/** 相对某天 00:00 偏移 N 个本地自然日；用 Date 构造器而不是减 86400000，跨 DST 也正确。 */
export function localDayStartWithOffset(dayStart: number, offset: number): number {
  const date = new Date(dayStart)
  return new Date(date.getFullYear(), date.getMonth(), date.getDate() + offset).getTime()
}

export function emptyActivity(now: number): ActivityStats {
  const start = localDayStart(now)
  const days: DayActivity[] = []
  for (let offset = -6; offset <= 0; offset += 1) {
    days.push({ start: localDayStartWithOffset(start, offset), delivered: 0, filtered: 0 })
  }
  return { today: days[days.length - 1] ?? { start, delivered: 0, filtered: 0 }, days }
}
```

要点：

- 创建时 replay 一次 `store.events()`，之后只处理新事件；O(1)/信号，`view` O(7)。
- 用 `payload.receivedAt` 分日；`event.time` 是入账时间，可能跨日边界。
- 7 天窗口含今天，共 7 个桶；`today` 与 `days` 最后一项一致。
- DST：用 `Date` 的年月日构造，不手写 86400000。
- 跨午夜：`view(now)` 每次现算窗口，不需要定时器。

### 7.4 `runtime/workers.ts`

```ts
import type { Session, SessionEvent, SessionId } from '@deepseek-ai/dsh-session'
import type { TokenUsage } from '@deepseek-ai/dsh-llm'
import type { L2Event } from '../../shared/events.ts'
import type { Projection } from '../projector/project.ts'
import type { HostContext } from '../context.ts'
import type { EventStore } from '../store/event-store.ts'
import type { WorkerRuntimeView } from '../../shared/runtime.ts'

interface WorkerRecord {
  sessionId: SessionId
  turn: number
  initialized: boolean
  lastActivityAt?: number
  usedTokens?: number
  windowTokens?: number
}

export class WorkerRuntimeRegistry {
  readonly #ctx: HostContext
  readonly #store: EventStore
  readonly #records = new Map<string, WorkerRecord>()
  readonly #disposers: (() => void)[] = []
  readonly #log?: (message: string) => void

  private constructor(options: { ctx: HostContext; store: EventStore; log?: (message: string) => void }) {
    this.#ctx = options.ctx
    this.#store = options.store
    this.#log = options.log
    // 启动时把还开着的工单会话登记进来；之后由 task/dispatched 增量登记。
    for (const ticket of options.store.projection().tickets) {
      if (ticket.workerSessionId !== undefined && ticket.stage !== 'ended') {
        this.track(ticket.workerSessionId as SessionId)
      }
    }
    this.#disposers.push(options.store.subscribe(event => this.onStoreEvent(event)))
    this.#disposers.push(options.ctx.on('session/event', (session, event) => this.onSessionEvent(session, event)))
  }

  static open(options: { ctx: HostContext; store: EventStore; log?: (message: string) => void }): WorkerRuntimeRegistry {
    return new WorkerRuntimeRegistry(options)
  }

  track(sessionId: SessionId): void {
    if (this.#records.has(sessionId)) return
    const record: WorkerRecord = { sessionId, turn: 0, initialized: false }
    this.#records.set(sessionId, record)
    this.ensureInitialized(record)
  }

  forget(sessionId: string): void {
    this.#records.delete(sessionId)
  }

  view(sessionId: string): Omit<WorkerRuntimeView, 'ticketId'> {
    const agent = this.#ctx.agents.get(sessionId as SessionId)
    const live = agent === undefined ? 'offline' : agent.status === 'running' ? 'running' : 'idle'
    const record = this.#records.get(sessionId)
    if (record === undefined) {
      return { workerSessionId: sessionId, live, turn: 0 }
    }
    this.ensureInitialized(record)
    const context = record.usedTokens === undefined
      ? undefined
      : { usedTokens: record.usedTokens, ...(record.windowTokens === undefined ? {} : { windowTokens: record.windowTokens }) }
    return {
      workerSessionId: sessionId,
      live,
      turn: record.turn,
      ...(record.lastActivityAt === undefined ? {} : { lastActivityAt: record.lastActivityAt }),
      ...(context === undefined ? {} : { context }),
    }
  }

  viewWorkers(projection: Projection): WorkerRuntimeView[] {
    return projection.tickets
      .filter(ticket => ticket.stage !== 'ended' && ticket.workerSessionId !== undefined)
      .map(ticket => {
        const sessionId = ticket.workerSessionId as string
        if (!this.#records.has(sessionId)) this.track(sessionId as SessionId)
        return { ticketId: ticket.id, ...this.view(sessionId) }
      })
  }

  close(): void {
    for (const dispose of this.#disposers) dispose()
    this.#disposers.length = 0
    this.#records.clear()
  }

  private initialize(record: WorkerRecord, session: Session): void {
    const route = session.requestContext()
    if (route?.contextWindow !== undefined) record.windowTokens = route.contextWindow

    // 一次性向前扫，初始化轮次 / 最近 usage / 最后活动；之后全部增量。
    // 与 sessions/observer.ts 的用法一致；Session 同步读已被标记 deprecated，
    // 若后续有替代 reader，只需替换这个方法。
    const events = session.snapshotEvents()
    for (let index = events.length - 1; index >= 0; index -= 1) {
      const event = events[index]
      if (event === undefined) continue
      record.lastActivityAt ??= event.time
      if (record.turn === 0 && event.type === 'turn/start') record.turn = event.data.turn
      if (record.usedTokens === undefined && event.type === 'assistant/message') {
        record.usedTokens = promptTokensOf(event.data.usage)
      }
    }
    record.initialized = true
  }

  /** 登记时 Agent 可能还没就绪；首次会话事件或下次快照读取时补一次初始化。 */
  private ensureInitialized(record: WorkerRecord): void {
    if (record.initialized) return
    const agent = this.#ctx.agents.get(record.sessionId)
    if (agent === undefined) return
    this.initialize(record, agent.session)
  }

  private onSessionEvent(session: Session, event: SessionEvent): void {
    const record = this.#records.get(session.id)
    if (record === undefined) return
    try {
      this.ensureInitialized(record)
      record.lastActivityAt = Math.max(record.lastActivityAt ?? 0, event.time)
      switch (event.type) {
        case 'turn/start':
          record.turn = event.data.turn
          break
        case 'assistant/message': {
          const used = promptTokensOf(event.data.usage)
          if (used !== undefined) record.usedTokens = used
          break
        }
        case 'request/context':
          record.windowTokens = event.data.contextWindow
          break
      }
    } catch (error) {
      // 观察是 best-effort：失败不能影响会话写入。
      this.#log?.(`worker runtime observation failed for ${session.id}: ${describe(error)}`)
    }
  }

  private onStoreEvent(event: L2Event): void {
    try {
      if (event.type === 'task/dispatched') {
        this.track(event.payload.workerSessionId as SessionId)
        return
      }
      if (event.type === 'task/closed') {
        const ticket = this.#store.projection().tickets.find(item => item.id === event.payload.ticketId)
        if (ticket?.workerSessionId !== undefined) this.forget(ticket.workerSessionId)
      }
    } catch (error) {
      this.#log?.(`worker runtime ledger observation failed: ${describe(error)}`)
    }
  }
}

/** 提示词侧 token：TokenUsage 的三个输入计数互斥，缓存命中/写入要加起来。 */
function promptTokensOf(usage: TokenUsage | undefined): number | undefined {
  if (usage === undefined) return undefined
  return usage.inputTokens + (usage.cacheReadTokens ?? 0) + (usage.cacheWriteTokens ?? 0)
}

function describe(error: unknown): string {
  return error instanceof Error ? error.message : String(error)
}
```

实现注意：

- `ctx.agents.get(sessionId)` 返回活 Agent；没有就 `offline`。这样账本说 running 但会话已经不在时，页面显示「会话不在线」，不谎报。
- `Agent.status` 是 live 状态：`running` 覆盖整个回合（含工具执行）；`idle` 是驱动未活动。
- `initialize` 在登记时扫一次；如果登记时 Agent 还没就绪，`ensureInitialized` 会在首次会话事件或下次快照读取时补一次。之后全部走 `session/event` 增量；不要每 2 秒全量扫。
- `snapshotEvents()` 的 deprecated 注意：现有 `sessions/observer.ts` 已在用；这里把调用收在 `initialize` 一处，未来替换成本最低。
- `request/context` 的 `contextWindow` 可能是 `undefined`（路由不报告）；直接赋值，表示清空旧值。
- `assistant/message` 没有 `usage` 时不覆盖上一次的值。
- `task/closed` 时从投影里找到该工单的 `workerSessionId` 并 forget；工单已结束，不再需要运行时记录。
- 所有观察异常只记日志，不冒泡；不能让运行时读模型影响会话或账本。`ensureInitialized` 内部也 try/catch：单个会话读失败只标记该记录并记日志，不能拖垮整个注册表。
- 如果 `viewWorkers` 碰到还没登记的会话，先 `track` 再读，避免启动顺序导致的空窗。

### 7.7 性能与缓存

- `EventStore.projection()` 按 append 缓存；**不要把“今天/7 天”放进这个缓存的投影**。它只在 append 时失效，跨过午夜但无新事件时会显示昨天的数。`activity` 在快照组装时现算，或用 `ActivityIndex` 维护。
- `ActivityIndex` 创建时 replay 一次；之后 O(1)/信号。
- `WorkerRuntimeRegistry` 只在 startup 做一次向前扫；之后 O(1)/事件。
- `workers` 数组 ≤ `maxWorkers`（只包含未结束且已派发的工单），快照体积可控。
- `activity.days` 固定 7 项。

### 8.4 纯选择器 `src/client/lib/overview.ts`

所有派生逻辑放这里，组件只渲染。输入即全部事实（snapshot + now），不读环境。

```ts
// 常量
export const CONTEXT_WINDOW_DISCOUNT = 0.8  // 标称窗口打八折
export const CONTEXT_WARN_RATIO = 0.6
export const CONTEXT_CRITICAL_RATIO = 0.8

// 上下文
export interface ContextMeterView {
  usedTokens: number
  windowTokens?: number
  effectiveWindow?: number
  ratio?: number
  level: 'normal' | 'warn' | 'critical' | 'unknown'
}
export function contextMeterOf(context?: WorkerContextUsage): ContextMeterView | undefined
export function contextPercent(ratio: number): number  // Math.floor(ratio * 100)

// 脉搏
export interface PulseView {
  state: 'running' | 'sensing' | 'idle' | 'no-router'
  lastActivityAt?: number
  clickable: boolean
}
export function pulseOf(snapshot: SnapshotResponse): PulseView

// 注意力
export type AttentionTarget =
  | { kind: 'tab'; tab: 'approvals' | 'tickets' | 'sources' }
  | { kind: 'session'; sessionId: string }
export interface AttentionItem {
  id: string
  kind: 'approval' | 'source-error' | 'worker-offline' | 'worker-interrupted' | 'context-critical'
  severity: 'warning' | 'danger'
  count: number
  target: AttentionTarget
  oldestAt?: number
  risk?: ApprovalRisk
  blockedCount?: number
}
export function attentionOf(snapshot: SnapshotResponse, now: number): AttentionItem[]

// Worker 舰队
export type WorkerDisplayStatus =
  | 'waiting' | 'running' | 'starting' | 'interrupted' | 'offline' | 'idle' | 'unknown'
export interface WorkerRow {
  ticket: TicketView
  runtime?: WorkerRuntimeView
  status: WorkerDisplayStatus
  /** 独立于展示状态：该会话是否没有活 Agent（含 blocked 但会话已离线）。 */
  offline: boolean
  context?: ContextMeterView
  turn: number
  elapsedMs: number
  waitingMs?: number
  lastActivityAt?: number
}
export interface FleetView {
  rows: WorkerRow[]
  occupied: number
  maxWorkers: number
  queued: number
}
export function fleetOf(snapshot: SnapshotResponse, now: number): FleetView

// 今天
export interface TodayView {
  start: number
  approvalsDecided: number
  approvalsPending: number
  ticketsCompleted: number
  ticketsFailed: number
  averageTicketMs?: number
  signals?: { delivered: number; filtered: number; total: number }
}
export function todayOf(snapshot: SnapshotResponse, now: number): TodayView

// 底栏
export interface FooterView {
  tickets: number
  approvals: number
  signals: number
  sourcesRunning: number
  sourcesError: number
  timers: number
}
export function footerOf(snapshot: SnapshotResponse): FooterView

// 空态
export function isFreshEmpty(snapshot: SnapshotResponse): boolean
```

实现规则：

- `contextMeterOf(undefined)` → `undefined`（还没有模型请求）。
- `contextMeterOf({ usedTokens })` 无窗口 → `{ usedTokens, level:'unknown' }`。
- `effectiveWindow = max(1, floor(window × 0.8))`；`ratio = used / effectiveWindow`。
- `level`：`ratio >= 0.8 → critical`；`>= 0.6 → warn`；否则 `normal`。
- `contextPercent` 用 `Math.floor`；`ratio` 可能 > 1，UI 只对环做 clamp。
- `pulseOf`：无 `routerSessionId` → `no-router`；否则 `running`/`sensing`/`idle`；`lastActivityAt` 取 signal/ticket/approval/worker 最大值；`clickable = routerSessionId !== undefined`。
- `attentionOf`：
  - pending approvals：`count`、`oldestAt`、`risk`、`blockedCount = stats.tickets.blocked`；target approvals。
  - `fleet.rows.filter(r => r.offline)`；target tickets。
  - `sources.filter(s => s.status === 'error')`；target sources。
  - `fleet.rows.filter(r => r.ticket.interrupted === true && !r.offline)`；target tickets。
  - `fleet.rows.filter(r => r.context?.level === 'critical')`；count 1 且能定位到单个 session 时 target session，否则 tickets。
  - 顺序：approval → offline → source → interrupted → context；每类最多一条。
  - 用 `offline` 标志而不是 `status === 'offline'`：blocked 且会话已离线的行展示状态仍是 waiting，但注意力条必须能看到离线。
  - 同一张工单 offline 与 interrupted 同时出现时只算 offline：interrupted 过滤掉 `offline` 的行。
  - 返回全部条目；组件只渲染前 2 条。
- `fleetOf`：
  - 工单集合：`stage !== 'ended' && workerSessionId !== undefined`。
  - `snapshot.workers` 缺失时，所有行 `status:'unknown'`、`offline:false`、`runtime: undefined`、`context: undefined`。
  - `snapshot.workers` 存在但某工单没有对应 runtime：`offline:true`（Host 说它是活会话但运行时没记录）。
  - `offline` 独立计算：`snapshot.workers !== undefined && (runtime === undefined || runtime.live === 'offline')`。
  - 状态判定严格按 §5.6 的顺序；blocked 的展示状态优先是 waiting，但 `offline` 仍为 true。
  - `context`：`offline || status === 'unknown'` 时为 `undefined`（显示 `—`，tooltip 用离线/未知文案）；其余 `contextMeterOf(runtime?.context)`。
  - `elapsedMs = max(0, now - (ticket.dispatchedAt ?? ticket.createdAt))`。
  - `waitingMs`：该工单最早 pending approval 的 `now - createdAt`。
  - `lastActivityAt = runtime?.lastActivityAt ?? ticket.updatedAt`。
  - 排序：waiting → running → starting → interrupted → offline → idle → unknown；同类 lastActivityAt 倒序，再 dispatchedAt 倒序。
  - `occupied = stats.tickets.running + stats.tickets.blocked`；`maxWorkers = capacity?.maxWorkers ?? MAX_WORKERS.defaultValue`；`queued = stats.tickets.queued`。
- `todayOf`：
  - `start = activity?.today.start ?? localDayStart(now)`；`lib/overview.ts` 自带一个本地 00:00 的 `localDayStart`，只用于 activity 缺失时的降级，正常情况用 Host 的 `activity.today.start`。
  - 审批：`decidedAt !== undefined && decidedAt >= start`；pending 为全部 pending。
  - 工单：`endedAt !== undefined && endedAt >= start`，按 outcome 分；平均耗时只取这些。
  - signals：`activity?.today` 转成 `{ delivered, filtered, total }`；缺失时 `undefined`。
- `footerOf`：见 §5.3。
- `isFreshEmpty`：`tickets.length === 0 && approvals.length === 0 && signals.length === 0 && sources.length === 0 && timers.length === 0`。

### 8.5 组件职责与结构

#### `Overview.tsx`

Props：

```ts
export interface OverviewProps {
  t: Translate
  language: string
  snapshot?: SnapshotResponse
  error?: string
  refresh: () => void
  actions: ConsoleActions
  onNavigate: (tab: ConsoleTabId) => void
  /** 渲染时刻；测试注入，缺省 Date.now()。 */
  now?: number
}
```

渲染分支：

1. `snapshot === undefined && error === undefined` → `<OverviewSkeleton t={t} />`。
2. `error !== undefined` → 顶部错误横幅（复用 `.pa-banner` / `.pa-banner__retry`，文案用现有 `approvalConnectionLost` / `approvalRefresh`），有 snapshot 时继续渲染内容，脉搏右侧显示 `overviewStale`；无 snapshot 时横幅 + 骨架。
3. `isFreshEmpty(snapshot)` → 脉搏 + 空态引导（不渲染舰队/今天/底栏）。
4. 正常 → 脉搏 → 注意力条 → 舰队 → 今天 → 底栏。

`const now = props.now ?? Date.now()`；每次 snapshot 轮询父级重渲染，相对时间自然更新。

#### `Pulse.tsx`

- 一行：`StateDot` + 状态文案 + 右侧最近活动/无活动/过期。
- 有 `routerSessionId` 且无 error 时整体是按钮，点击 `actions.openSession(routerSessionId)`；`title`/`aria-label` 用 `overviewPulseOpenRouter`。
- 状态映射：`running` → `ongoing`；`sensing` → `done`；`idle` → `idle`；`no-router` → `warning`。
- 文案：`overviewPulseRunning` / `overviewPulseSensing` / `overviewPulseIdle` / `overviewPulseNoRouter`。
- 右侧：`overviewPulseLastActivity`（传 `formatRelativeTime`）或 `overviewPulseNoActivity`；error 且有 snapshot 时用 `overviewStale`。

#### `AttentionBar.tsx`

- 输入 `items`（全部）、`now`、`onActivate`、`t`、`language`。
- 只渲染前 2 条；`items.length > 2` 时追加 `overviewAttentionMore`。
- 每条：`Tag`（kind 文案 + tone）+ 主文案 + 副文案 + 箭头；整行按钮。
- 主文案按 kind/count：
  - approval：`overviewAttentionApprovalOne/Many`
  - source：`overviewAttentionSourceErrorOne/Many`
  - offline：`overviewAttentionOfflineOne/Many`
  - interrupted：`overviewAttentionInterruptedOne/Many`
  - context：`overviewAttentionContextOne/Many`
- 副文案：
  - approval：`overviewAttentionWait`（`formatDuration`）+ `overviewAttentionRisk`（`t(riskKey)`）+ `overviewAttentionSlotsOne/Many`（`blockedCount > 0`）；用 ` · ` 连接。
  - source：`overviewAttentionSourceHint`。
  - 其他：无。
- `Tag` 文案：`overviewAttentionApproval/Source/Worker/Context`；tone：warning → `warning`，danger → `danger`。
- `data-severity` 用于背景/边框色。
- 空数组返回 `null`。

#### `WorkerFleet.tsx` + `WorkerRow.tsx`

- `WorkerFleet`：头部（`overviewFleetTitle` + occupied/max + 槽位 + `overviewFleetQueue`）+ 行 + 空态/更多。
- 行数 > 5：只渲染前 5，追加 `overviewFleetMore`（按钮，去工单页）。
- 0 行：`overviewFleetEmpty` + `overviewFleetEmptyHint`，不渲染空卡片。
- `WorkerRow`：
  - 整行 `<button type="button" className="pa-overview__worker" data-status={status} onClick={() => actions.openSession(runtime.workerSessionId)}>`
  - 左 `StateDot`：waiting/running/starting/interrupted/offline/idle/unknown 映射见 §5.6。
  - 标题（`ticket.title`）+ 右侧 `ContextMeter`。
  - 副行：`工单 #{shortId}` + 状态/轮次/时长；右侧最后活动/等待时长。
  - `title` 属性给完整标题；`aria-label` 包含标题、状态、上下文和 `overviewWorkerOpen`。
- `ContextMeter`：
  - `meter` 存在且有 `ratio`：`{t('overviewContextLabel')} {percent}%` + 环。
  - 有 used 无 window：`{t('overviewContextLabel')} {tokens}` + 虚线环。
  - 无 context：`{t('overviewContextLabel')} {t('overviewUnknown')}`。
  - tooltip：
    - 有 window：`overviewContextTooltip`，参数 `used`、`effective`、`left`、`window`（用 `formatTokens`）。
    - 无 window：`overviewContextNoWindow`，参数 `used`。
    - 无 context 且离线：`overviewWorkerOffline`；无 context 且未知：`overviewWorkerUnknown`；其余无 context：`overviewContextNoUsage`。
  - 环的 `data-level`：normal/warn/critical；无 ratio 时 `unknown`（虚线）。
  - SVG `aria-hidden`；文字承担可访问名称。
- 副行时长：
  - running/starting：`第 {turn} 轮 · {formatDuration(elapsed)}`（turn=0 只显示启动中）。
  - waiting：`等待审批`，右侧 `已等 {formatDuration(waitingMs)}`。
  - interrupted/offline/idle/unknown：状态词，右侧 `formatRelativeTime(lastActivityAt)`。

#### `TodayPanel.tsx`

- 标题 `overviewToday` + 右侧 `overviewTodaySince`。
- 三个 tile：
  - 审批：`overviewTodayApprovals` / `overviewTodayApprovalsSub`（decided, pending）。
  - 工单：`overviewTodayTickets` / `overviewTodayTicketsSub`（completed, failed）；失败 >0 红色；有平均耗时时 `title={t('overviewTodayTicketsHint', { duration })}`。
  - 事件：`overviewTodayEvents` / `overviewTodayEventsSub`（delivered, filtered）；`signals === undefined` 时大数字和副行都用 `overviewUnknown`。
- 三格只读。

#### `ActivityChart.tsx`

- 标题 + 图例（`overviewChartDelivered` / `overviewChartFiltered`）。
- 7 根柱；投递在下、过滤在上；今天 `data-today="true"`。
- 每根柱 `title` / `aria-label` 用 `overviewChartDay`（星期、投递、过滤）。
- 全 0：`overviewChartEmpty`。
- 高度 54px；无动画。

#### `OverviewFooter.tsx`

- 左：`overviewTotals`（`Intl.NumberFormat(language)`）。
- 右：来源运行数（`overviewSources`）+ 异常数（`overviewSourcesError`）+ 定时数（`overviewTimers`）；都为 0 时隐藏右侧。
- 10px tertiary。

#### `OverviewSkeleton.tsx`

- 3–4 个灰色块，`aria-busy="true"`，`aria-label={t('overviewLoading')}`。
- 不显示具体数字，避免加载瞬间闪出 0。

### 8.9 格式化辅助

在 `src/client/lib/format.ts` 增加：

```ts
/** 时长：<1 分钟用词典短句，其余用 Intl unit；用于已运行/已等待/平均耗时。 */
export function formatDuration(t: Translate, language: string, ms: number): string {
  const minutes = Math.max(0, Math.floor(ms / 60_000))
  if (minutes < 1) return t('overviewLessThanMinute')
  const formatter = new Intl.NumberFormat(language.length > 0 ? language : 'en', {
    style: 'unit',
    unit: minutes < 60 ? 'minute' : 'hour',
    unitDisplay: 'narrow',
    maximumFractionDigits: 0,
  })
  if (minutes < 60) return formatter.format(minutes)
  const hours = Math.floor(minutes / 60)
  const rest = minutes % 60
  return rest === 0 ? formatter.format(hours) : `${formatter.format(hours)} ${new Intl.NumberFormat(language, { style:'unit', unit:'minute', unitDisplay:'narrow' }).format(rest)}`
}
```

- 先取整到分钟；不足 1 分钟用 `overviewLessThanMinute`。
- 小时+分钟用空格连接；zh 为「2小时 5分钟」，en 为「2 hr 5 min」；可接受。
- `formatTokens(language, count)` 放 `lib/overview.ts` 或 `format.ts`：

```ts
export function formatTokens(language: string, count: number): string {
  return new Intl.NumberFormat(language.length > 0 ? language : 'en', {
    notation: 'compact',
    maximumFractionDigits: 1,
  }).format(count)
}
```

- `formatDayLabel(language, start)` 用 `Intl.DateTimeFormat(language, { weekday:'short' })`。
- `formatNumber(language, n)` 用 `Intl.NumberFormat`（底栏千分位）。

## 14. 风险与注意事项

1. **上下文口径**：0.8 折算是产品策略；代码注释写清“标称 1M 经常达不到”。如果以后要按模型/服务商配折扣，把常量升级为配置，不要散落在组件里。
2. **TokenUsage 互斥**：`inputTokens` 不含缓存；必须加 `cacheReadTokens` / `cacheWriteTokens`；不要用 `totalTokens`。
3. **Session 同步读已 deprecated**：`snapshotEvents()` 只用于 `WorkerRuntimeRegistry.initialize` 的一次性初始化；新事件全部走 `session/event`。若 Session 提供替代 reader，只改这一处。
4. **投影缓存**：`EventStore.projection()` 只在 append 时失效；不要把“今天/7 天”放进缓存投影，否则跨午夜会错。
5. **快照 optional 字段**：Host 同版本总是提供；客户端缺省分支只用于旧夹具/降级。不要因为可选字段就省略 Host 侧实现。
6. **2 秒轮询**：上下文/状态最多落后 2 秒；文案用“上次请求”“最近活动”，不要承诺实时。
7. **Agent registry**：`ctx.agents.get` 可能没有活 Agent；一律按 offline 展示，不要用账本阶段推断“正在执行”。
8. **maxWorkers 可到 100**：槽位段超过 8 必须退化比例条；Worker 行最多 5 条。
9. **i18n guard**：新增键必须同时在 zh/en 且有使用点；删除 Placeholder 时同步删 `notAvailable` / `notAvailableHint`。
10. **style guard**：组件里每个 `pa-*` 类都要在 `CONSOLE_CSS` 定义；用 data 属性表达状态，减少类数量。
11. **警告 token**：宿主 token 是 `--dsw-alias-state-warn-primary` / `--dsw-alias-state-warn-label`（已核对 primitives 包），不要写成 `warning`。
12. **客户端组件测试无 DOM**：现有测试用 `renderToStaticMarkup`；点击交互靠手动矩阵验证，纯选择器覆盖逻辑。
13. **默认页变更**：概览成为默认页后，用户打开总控台不再直接落在审批；审批徽标 + 注意力条必须在首屏可见，否则会漏审批。
14. **不新增依赖**：图表/环都用 CSS/SVG，不引第三方图表库。

### 18.1 与本文的差异

| 位置 | 落地方式 | 原因 |
|---|---|---|
| `FleetView` | 增加 `running` / `blocked` 两个计数字段 | 槽位段要区分「蓝=执行、琥珀=等审批」，只靠 `occupied` 画不出来。 |
| `WorkerRow` | 增加 `workerSessionId: string` | 行点击统一用视图里的会话 id，不在组件里再对可空字段做断言。 |
| `fleetOf` / `viewWorkers` | 只收 `running` / `blocked` 工单 | `append` 工单在排队时就带 `workerSessionId`；若按「未结束 + 有会话」筛选，会出现「进行中 0/5」却渲染一行。 |
| `AttentionBar` | 增加 `pa-overview__attention-tag` 类 | 320px 下官方 `Tag` 会被压成两行（「审 / 批」），需要 `flex:0 0 auto; white-space:nowrap`。 |
| `Overview` 错误分支 | 直接复用现有 `.pa-banner` 与 `approvalConnectionLost` / `approvalRefresh` | 连接中断的文案与行为与审批页一致，不新增重复 key。 |
| `tests/host/perception/service.test.ts` | 合并重复的 `afterEach`，目录删除加 `maxRetries` | Windows 上脚本子进程的句柄可能晚于 `stop()` 释放，全量测试偶发 EBUSY；与概览无关。 |
