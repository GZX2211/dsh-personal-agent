# 总控台设置页开发方案

## 1. 目标

把总控台「设置」标签页（当前 `Placeholder`）实现为三块配置，全部适配右侧栏窄区域（约 500px）：

| 分块 | 内容 | 面向 |
|---|---|---|
| 派单规则 | 结构化规则列表（名称、说明、启停），装配进 Router 提示词的「派单规则」段；显示策略版本 | Router |
| 执行器 | 模型（服务商/模型/推理强度，只读取自官方目录）、并行工单数、执行环境根目录 | Worker |
| 提示词 | 共享约定 / Router 角色 / Worker 角色三份文本编辑；整体版本历史；与默认比较 | Router + Worker |

## 2. 已确认决策

1. **派单规则**：结构化规则列表；空列表起步；可增删、可启停；策略版本 = 规则集的 sha256 前 8 位；只有启用规则进入提示词。
2. **提示词编辑范围**：三份独立文本（shared / router / worker），每次保存生成一个整体版本。
3. **版本操作**：保存产生不可变版本；历史可只读预览、可载入编辑器（再保存才生效）、可与内置默认逐行比较、可复制全文；不会自动取新默认。
4. **生效时机**：
   - 提示词与派单规则：下一次模型请求生效（`systemPrompt.section` 接受函数文本，无需重启）；
   - 执行器模型：只对之后新建的 Worker 生效（已存在 Worker 不追改）；
   - 并行工单数：立即影响调度，但**不截断已有任务**——改小后新派发排队，等占用自然回落到新上限以下才继续放行；
   - 执行环境根目录：只影响之后新建的工单目录。
5. **存储**：`<stateDir>/settings.json`（当前执行器 + 规则 + 设置 revision，乐观锁）+ `<stateDir>/prompt-history.jsonl`（append-only 提示词版本快照）。
6. **模型字段**：服务商 / 模型 / 推理强度均为只读下拉，选项取自官方 `ctx.llm` 目录；全空 = 继承 DSH 默认（显示当前默认值）。已保存但目录中已不可用的值保留原值并标记不可用。
7. **导航**：设置页顶部分段切换三块；提示词页内再分「编辑 / 完整提示词 / 历史」。
8. **并行工单数范围** 1–100，默认 5；**根目录** 必须是绝对路径，不存在也允许保存（建工单时自动创建）。

## 3. 契约

### 共享契约 `src/shared/settings.ts`

- 类型：`PromptPart`、`PromptTexts`、`DispatchRule`、`WorkerModel`、`ExecutorSettings`、`ModelCatalogView`、`PromptVersion(Summary)`、`SettingsView`、保存请求/响应。
- 纯函数：`parseDispatchRules`、`parsePromptTexts`、`parseExecutorSettings`、`ruleIdOf`、`composeDispatchSection`、`composeRolePrompt`、`promptStats`、`countParagraphs`、`isAbsoluteDirectory`、`formatWorkerModel`。

### 路由（`src/shared/api.ts`）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/personal-agent/api/settings` | 一次性读取设置视图（含模型目录、提示词当前版本/默认/历史摘要） |
| POST | `/personal-agent/api/settings/executor` | 保存执行器（body：`{executor, revision}`） |
| POST | `/personal-agent/api/settings/policy` | 保存派单规则（body：`{rules, revision}`） |
| POST | `/personal-agent/api/prompts` | 保存提示词版本（body：`{texts, baseRevision}`） |
| GET | `/personal-agent/api/prompts/:revision` | 读取指定提示词版本的完整文本 |

新增稳定错误码：`settings-invalid`（400）、`settings-conflict`（409）、`prompt-conflict`（409）、`prompt-revision-not-found`（404）。

## 4. Host 模块

| 模块 | 职责 |
|---|---|
| `settings/policy.ts` | 策略版本 hash（纯函数） |
| `settings/store.ts` | `settings.json` + `prompt-history.jsonl` 的读写、revision 乐观锁、损坏降级 |
| `settings/model.ts` | 从 `ctx.llm` / `ctx.agentDefaultModel` 构建模型目录视图（providers / models / reasoning / default），provider 级失败隔离 |
| `settings/service.ts` | 业务操作：视图组装、保存校验、提示词装配、`maxWorkers()`、`executorRoot()`、`workerModel()` |
| `settings/errors.ts` | `SettingsInputError` / `SettingsConflictError` / `PromptConflictError` / `PromptRevisionNotFoundError` |

接入点：
- `sessions/decorate.ts`：section text 改为动态函数，读取设置服务；
- `dispatcher/scheduler.ts`、`tools/pa_task_route`：`maxWorkers` 由数值改为 getter；
- `dispatcher/executor.ts`、`sessions/worker.ts`：根目录与 Worker 模型种子；
- `console-api/server.ts`：设置端点分派；
- `index.ts`：装配。

## 5. Client 模块

- `lib/settings.ts`：提示词统计、行级 diff、规则草稿校验、模型候选、执行器草稿校验、错误文案映射。
- `lib/http.ts`：设置读写请求。
- `hooks/useSettings.ts`：打开时拉取 + 手动刷新。
- `views/Settings.tsx` + `components/settings/*`：三段导航、规则编辑器、执行器编辑器、提示词编辑器（编辑/完整/历史）、保存条。
- `style.ts`：窄区域样式（`pa-settings*`）。
- `i18n.ts`：全部新增文案 zh/en。

## 6. TDD 与提交顺序

1. `feat(settings)：共享设置契约与派单规则领域`（shared/settings + host/settings/policy）
2. `feat(settings)：设置存储与提示词版本历史`（host/settings/store）
3. `feat(settings)：设置服务与模型目录`（host/settings/service + model + errors）
4. `feat(prompts)：提示词按当前设置动态装配`（decorate + fake-host）
5. `feat(dispatcher)：并行工单数动态读取`（scheduler + pa_task_route + index）
6. `feat(sessions)：执行器模型与根目录`（worker + model + executor）
7. `feat(console-api)：设置读写端点`（shared/api + server + index）
8. `feat(client)：设置页纯逻辑`（lib/settings）
9. `feat(client)：设置页界面`（views/components/style/i18n）

每个闭环：红用例 → 实现转绿 → 三角测量（契约允许但测试未覆盖的输入）→ 重构 → 全量测试 → 提交。
