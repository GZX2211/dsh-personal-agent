# P3 开发规划（总控台 UI / 样式阶段）

> 临时协作文档（`collab/md/`），不进 `docs/`，不需要英文版。
> 依据：用户 2026-11-15 的样式要求 + 官方 `ask_user_question` 源码（已从 `app.asar` 取出，见 `collab/scr/ref/`）。
> 状态：**已交付（0.3.0）**，C1–C5 五个原子提交完成；待用户 GUI 目检。交接记录见 `personal-agent-交接备忘.md` §12。

---

## 0. 已确认口径（用户原话归纳，作为唯一裁判）

1. **审批卡展开态 = 官方 `ask_user_question` 提问卡 1:1**（官方源码为准），
   唯一多出的是：卡顶 `发起者 / 关联工单 / 时间`，卡底 `附件`。
2. **折叠态 = 图片 1:1**，即官方的 minimize 形态（头部 + 题干两行截断）。
3. **所有 Token 用官方的**：圆角、字号、行高、颜色、阴影一律走宿主 design token；
   不为了贴图而自造像素值（用户明确否决"为 1:1 丢弃统一化"）。
4. 移除 `title`、`fields`；人的回答 = 选项 + 「输入你的答案」自由文本（写入 `note`）。
5. `附件` 由 **AI** 填（`pa_approval_submit` 新参数），人只读；点击用宿主右侧栏打开文件。
6. `发起者` = 发起审批的 Agent 会话，点击跳转到该会话；`关联工单` 点击切到工单页。
7. 工单卡：与审批卡同一套卡片与头部；**不要阶段徽标、不要汇报摘要、不要排队原因**；
   「阻塞中」「已中断」两个副标签保留；工单卡无展开态。
8. 排除项：图片里的红色方框、`时间范围` 按钮。
9. `?` 帮助按钮保留并可点，弹出说明浮层。
10. 已决审批卡 = 官方 review 只读态。

## 1. 契约变更（C1 批次）

### 1.1 删除（含兼容路径）

| 位置 | 变更 | 兼容路径 |
|---|---|---|
| `shared/approvals.ts` | 删 `APPROVAL_FIELD_TYPES` / `ApprovalFieldType` / `ApprovalField` / `ApprovalFieldValue(s)`；`ApprovalDecision.fields`、`ApprovalView.fields`、`ApprovalView.title` 删除 | 旧账本行仍能被重放：`payload-spec` 只校验已声明键，未声明的 `title`/`fields` 直接忽略；`project` 不再读取它们 |
| `shared/api.ts` | `DecisionRequest.fields` 删除 | 服务端 `parseDecisionRequest` 对未知键保持宽容（不报错、不落账） |
| `shared/events.ts` | `ApprovalPendingPayload` 删 `title`/`fields` | 同上 |
| `host/tools/pa_approval_submit` | 删 `title` 参数与 `fields` 解析 | 旧调用（含这两个参数）仍能执行：解析器只读已知键 |
| `host/approvals/service.ts` | 删 fields 解析与必填校验 | — |
| `host/approvals/message.ts` | 删「填写字段」段，保留 `补充说明` | — |
| `host/tools/pa_ledger_query` | 审批行不再用 `title`，改用题干预览 | — |

### 1.2 新增

- `ApprovalPendingPayload.attachments?: string[]`（可选，AI 提供的文件路径）
- `ApprovalView.attachments?: string[]`
- `pa_approval_submit` 参数 `attachments?: string[]`：非空字符串、去重、最多 20；无文件系统 IO（不校验存在性）。
- `payload-spec`：`approval/pending.optional.attachments = { type: 'strings' }`。
- `prompts/worker.md`：说明 `attachments` 与「输入你的答案」= note 的用法。

### 1.3 行为决策

- 附件路径按「工单工作目录或绝对路径」解释，展示取 basename；
  点击用 `absoluteFileAddress(path)`（官方语法）构造 `dsh-resource://file/absolute/...` 再 `openResource`。
  相对路径由 Host 在工具参数校验时归一化为绝对路径（基于工单 `directory`），避免客户端猜基准目录。

## 3. 过滤条与页面

- `.pa-filterbar`：`padding: 8px 16px`，左胶囊组（`待审批/已通过/全部`）、右搜索框 + `?`。
- 胶囊：`height:28px`、`padding:0 12px`、`radius md`；选中 = `interactive-bg-hover` 底 + `label-primary` 字，未选中 = 透明底 + `label-tertiary`。
- 搜索框：`height:32px`、`radius md`、`bg-layer-1` 底 + `--dsw-elevation-soft` 发丝描边（浅色主题可见）；左侧放大镜，placeholder `label-caption`。
- `?`：24px icon button，点击弹出说明浮层（tooltip 面板样式，双语）。
- 工单页胶囊：`待处理/进行中/已结束/全部`，与审批页同一套组件。
- 列表滚动：过滤条固定，列表区独立滚动（`overflow-y:auto`）。

## 4. TDD 批次与原子提交

| 批次 | 内容 | 红用例 |
|---|---|---|
| C1 | 契约清理 + `attachments` 贯通（shared → payload-spec → project → 工具 → 决定 → 消息 → 查询 → prompts） | `payload-spec`（拒绝非字符串数组 / 接受旧行 title+fields）、`project`（attachments 透出、title/fields 忽略）、`pa_approval_submit`（attachments 校验/去重/上限/相对路径归一）、`service`（无 fields 校验、note 落账）、`message`（无「填写字段」段） |
| C2 | 客户端纯逻辑：`lib/filter.ts`（胶囊 + haystack）、`lib/approvals.ts`（note-only 决定）、`lib/files.ts`（地址 + basename）、`lib/format.ts`（绝对时间）、`lib/tickets.ts`（副标签）、i18n | filter 交集/排序/空查询、buildDecision 边界、fileAddress 转义、日期格式 zh/en、副标签派生 |
| C3 | 卡片组件 + 审批页（官方样式移植） | 组件级纯逻辑（分页进度、折叠默认态、review 判定）、错误码文案 |
| C4 | 工单页 + 过滤条 + 帮助浮层 + 标签徽标 + 面板接线（openSession / openResource / 切页 action） | 页面状态与动作面 |
| C5 | 文档、交接备忘、冒烟脚本、构建、真实宿主重载 + 探针 | 冒烟 23→N 项 |
